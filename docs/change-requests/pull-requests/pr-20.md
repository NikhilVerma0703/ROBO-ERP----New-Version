## Robo module — round of 25 Sep 2026

Six changes on the Robo shop-floor module. Nothing outside Robo is touched, and there is no schema change.

### 1. Downloads → QC Rejection Analysis: Robo-line faults only
Counts only the two QC faults the Robo line causes, Spillage and Pattern Problem in QC Line, instead of every fault QC recorded (Crack, Pinhole, Oil Dot, Chipout…). Only C (Reject) slabs count, each once. Rejection Rate = Robo-line rejects ÷ Total Slabs Produced × 100 (20 / 250 = 8%). The table always lists both faults, showing 0 when one did not occur.

### 2. Downloads → Reference Sheet: Reports' own figures
Total Slabs Produced, Total Production Time, Total Delays and Avg Slabs/hour now come from the same function Reports uses (moved into `reportSummary.ts`), for the design's latest batch taken whole. The sheet can no longer read 322 where Reports reads 359 for D-1445. Robot delays are listed longest first, with a pie of the top 3 below the table.

### 3. Reports → Production Rate per Hour: slabs drawn where they were made
Two recording slips (a production date one day off, or an Out typed a few minutes before its own In) put slabs exactly one day away. So D-1432 (31 Aug only, 11:20 → 22:31) showed points on 1 Sep and read 34 h 40 m / 3.6 slabs/hr. A slab now moves by one day only when its neighbours in slab-number order clearly sit on that day beside its clock time. Nothing is written back. D-1432 now reads 11 h 11 m / 11.3. The chart subtitle shows the run's first In and last Out, e.g. "31/08/2026 (11:20) → 31/08/2026 (22:31)". The chart cap goes from 4 to 8 days (D-1449 ran 17 → 23 Sep).

### 4. Reports → Daily Slabs / Hour Trend: by date
This used to be slabs ÷ the open time of silent shift rows, which read 19/09 as 279.3. It is now slabs whose Production Date is that date ÷ hours the Robo line ran on that date, taken from the slabs' own In/Out times. Delays are kept; stops longer than 2 hours (a power cut, the line off overnight) are not counted; time is split at midnight. A full day divides by 24, and 07:00 → 20:00 divides by 13. The Y-axis runs 0–10 in steps of 2. Daily Production Trend and Day-wise Delay Analysis are unchanged.

### 5. Robo Entry: next S.No. and Slab Number stay in sequence
After a refresh, a trip to another page or an edit, the server offered a pair from an older batch on the same shift (61 after 13). It now reads the last slab saved on the running shift: after 13 / 161223 it offers 14 / 161224, every time. The POST's own S.No. uses the same logic, and responses are not cached. The count-on after each save is unchanged.

### 6. Robo Entry → "Delays This Slab": responsive layout
Layout only. Row 1 is the Delay Code alone, with the full description shown ("C10 Bowl Dry Cleaning ROBOT"; it wraps instead of being cut off). Row 2 is Start, End and Duration. Row 3 is Remarks. For robot codes, Machine(s) sits between rows 2 and 3, and Remove moves to the label line. Touch targets are 44 px on tablet and phone. Checked at 390, 810, 1180 and 1440 px.
