## Robo + Chromia — round of 18 Oct 2026

Four changes. Three need a database change, and all three are already applied to Neon (additive only — one new nullable column and three new tables; nothing existing was altered or dropped).

### 1. Shift on every slab
`RoboShift.shiftNumber` looks like the place for a shift and is not: it is one row per day, stamped from the wall clock when the tablet is first opened and shared by every slab of that day, so it read the same on a slab made at 07:00 and one made at 23:40. That is why Shift had been removed from Complete Details and both Excel sheets.

This adds the thing it was mistaken for — the A/B/C the operator picks, stored on the slab:

- **Robo Entry → Slab Entry**: a Shift dropdown beside Production Date (Shift A 06:00–14:00, B 14:00–22:00, C 22:00–06:00). It follows the In Time typed below until the operator picks one by hand, so a handover corrects itself.
- **Slab Records**: a Shift column between Production Date and Design Name; the last heading now reads Review.
- **Complete Details**: the slab's Shift beside its Production Date.
- **Excel**: Shift immediately after Production Date on Complete Production and Delay List. The importer reads a Shift column back, in letters or 1/2/3.
- The 5,780 slabs already in the register keep a NULL column and report the shift their own In Time falls in (1,627 A / 2,035 B / 2,117 C). Nothing was back-filled and nothing is written back on read.

Database: `ALTER TABLE "RoboProductionRecord" ADD COLUMN "productionShift" TEXT;`

### 2. Production Rate per Hour — shift-wise colours
Still one continuous line over the selected batch's run, with the same batch filter, the same hourly counts by Out Time, the same timeline, empty hours kept and the same midnight handling. What changed:

- The line's colour says which shift each hour belongs to — red on A, dark blue on B, dark green on C — turning exactly on 06:00 / 14:00 / 22:00. It is a hard-stopped gradient on the single path, not three series, so the trend stays one unbroken curve.
- A band under the time labels names each stretch: SHIFT A / SHIFT B / SHIFT C, bold capitals in the shift's colour, centred on the hours it covers and repeating across days.
- Date dividers are 2px with bold dates; both axes are named ("Number of Slabs", "Time Duration (in Hours)").
- The colours are measured, not picked by eye: plain dark red against dark green is ΔE 2.0 under protanopia (indistinguishable). The lightened steps used here pass every check at ΔE 8.5, and the bold shift names carry the same information without colour at all.
- Historical batches need nothing — the shift of an hour comes from the clock.

### 3. Hourly chart tooltip — the hour's delays
Hovering an hour now also lists every delay that began in it, with its code, duration and start–end, then the hour's total. An hour with none says "No delays" and totals 0 minutes. Each delay is shown whole under the hour it started, so the total is exactly the sum of the lines above it. On tablet and phone the same reading opens in a panel under the chart on a tap, because the plot is wider than a phone and a floating card ends up off the edge.

### 4. Attendance — one register for both ERPs
A new last section in both the Robo and Chromia ERPs. There is one register, not two kept in step: one set of tables, one page component and one handler, mounted at `/api/robo/attendance` and `/api/chromia/attendance` so each inherits its own module's existing gate. `(date, operator)` is unique, so the same day entered from either ERP is the same row and a duplicate cannot be created.

- **Daily Attendance**: a date, then the roster alphabetically with Line (Robo / Chromia / both), In-Time, Out-Time, Total Working Hours and Edit. One In and one Out per operator per day however many lines they worked. Times use the Slab Entry input (1625 → 16:25, 1367 refused); hours appear as the Out is typed; a 22:00–06:00 night shift reads as 8h. Add / rename / remove operators — one with attendance on record is taken off the roster rather than deleted.
- **Request Leave**: empty to start. Date, S.No., Operator, Leave Time (from–to, blank for a full day), Reason, Remarks, with Edit and Remove. S.No. is the row's position in its date, computed not typed.
- **Downloads**: record type, operator and one period (a date, last week, month-wise, a custom range, all records), combining. Results are shown on the page and the Excel is built from the same query.

Database: three additive tables `attendance_operator`, `attendance_day`, `attendance_leave`, seeded with the two named operators.
