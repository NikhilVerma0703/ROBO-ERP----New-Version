# PR #18 — Robo: Production Rate per Hour date fix, slab Edit fields, S.No. under filters, Reference Sheet
State: CLOSED  Merged: null

## What's in this PR

Four Robo module changes, plus the batch-split base patch they build on:

### 1. Slab Edit — Batch Number, Design & Target Slabs inline
The slab Edit view now shows Batch Number, Design and Target Slabs inline alongside
Production Date and Thickness, each with an "apply to this slab and every following
one in the batch, up to the next change" option. Includes the mixed-batch split base
patch (re-parenting a slab to a corrected batch via batchSplit.ts). No schema change.

### 2. Slab Records — S.No. under every filter
S.No. now stays 1…N and visible under any filter/search, not only a Batch No. search.
The sequence is computed over the full batch, so a filter never blanks or renumbers
it. No other filtering logic changed.

### 3. Reference Sheet — robot delays, Robos, programs, formatting
The Reference Sheet download now lists Robot Delays correctly: matched by delay CODE
(C1…C20), not the inconsistent stored category (which had left the section empty),
grouped per code with the Robos responsible and the combined minutes. Robo Program
Names show one row per program (only the Robos actually used). The note row and the
website description blurb are removed. Design-name search is case-insensitive. No
schema change.

### 4. Production Rate per Hour — date/hour drift fixed at the root
The hourly chart rebuilt each slab's day from serialNumber order plus time-wrap
detection. serialNumber is unreliable on old runs, so the walk ran out of order, every
out-of-order step looked like a midnight crossing and advanced the day cursor, and
whole batches drifted forward by 1–15 days (1440, 8–10 Sep, showed 23–25 Sep; 1445,
15–16 Sep, showed 18–20 Sep); the length cap then framed the window on the wrong dates.
Now each slab is placed on its OWN stored production date, In = date + In time and
Out = date + Out time (Out rolled to the next day only when it precedes In — the
overnight rule), counted in its Out hour, with the timeline running earliest In →
latest Out. No serial number, no wall clock. A genuinely wrong stored date is corrected
on the slab (Slab Records → Edit), not reconstructed away. No schema change.
